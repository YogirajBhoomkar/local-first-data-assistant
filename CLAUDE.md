# CLAUDE.md

RULES FOR THIS REPO — follow them in every step

Git and safety
- Work only on the current local branch. Never push, never add a remote, never force anything.
- Commit in small steps with clear messages. Do not rewrite history.
- Never read, print, or create .env or .env.* files other than .env.example. Never print secrets, API keys, tokens, hostnames of private services, or user file paths in logs, tests or docs.
- Do not use real client names, real company data, or real people's names anywhere: code, comments, fixtures, test data, docs, commit messages. Use only synthetic data generated by our own scripts.

Privacy rules of the product (never weaken these to make something work)
- User files never leave the machine as whole files.
- Only the privacy gate module may build anything that goes to the remote model. No other module calls the remote model with data.
- Every remote call is written to the egress log before it is sent.
- If a step would need to break one of these rules, stop and report instead of working around it.

Engineering
- Node 22 (>= 22.13), TypeScript strict mode, ES modules, npm workspaces.
- Pin exact versions in package.json (no ^ or ~).
- Before using any library API, check it in the installed package's type definitions or its docs. Do not guess APIs from memory. If an API differs from what a prompt says, follow the real API and note the difference in the phase notes.
- Ask before adding a dependency that is large, native, or not named in the prompt.
- Keep the core logic free of Electron and UI code. Core talks to the outside only through the interfaces in packages/core/src/ports.
- Every new module gets unit tests (Vitest). Before you say a phase is done: typecheck, lint and all tests must pass.
- At the end of each phase write docs/phases/phase-N.md: what was built, decisions taken and why, how to run it, known gaps, and anything in the prompt that turned out to be wrong.

## Repo map

- `packages/core` — domain types, config, ports (interfaces only). No I/O except via ports.
- `packages/engine` — local data engine (DuckDB). Phase 1.
- `packages/models` — local and remote model adapters. Phase 2.
- `packages/docs` — PDF/PPTX extraction and keyword search. Phase 4.
- `packages/agent` — orchestrator, router, privacy gate. Phase 3.
- `apps/cli` — developer CLI. `apps/desktop` — Electron app (Phase 5).
- `scripts/` — probe, synthetic data generator. `eval/` — question set and reports.
- `docs/` — architecture, phase notes. `plan.md` — the phase-by-phase build plan.
